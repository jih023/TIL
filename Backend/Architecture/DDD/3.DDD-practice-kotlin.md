# DDD(Domain Driven Design) practice - kotlin

> 2.DDD-practice-java.md에서 작성한 동일한 도메인을 코틀린으로 다시 작성하기 

## Java → Kotlin 매핑
 
| Java | Kotlin |
|---|---|
| `public record Money(...)` | `data class Money(val ..., val ...)` |
| compact constructor `public Money { ... }` | `init { ... }` 블록 |
| `if (...) throw new IllegalArgumentException(...)` | `require(...) { "msg" }` |
| `if (...) throw new IllegalStateException(...)` | `check(...) { "msg" }` |
| `public static` 메서드 | `companion object { fun ... }` |
| `private final Long id` | `val id: Long` (val이 곧 final) |
| private setter + public getter | `var x: T = ...; private set` |
| `Optional<T>` | `T?` (nullable) |
| `Objects.requireNonNull(...)` | (불필요 — 타입 시스템이 처리) |

## Kotlin에서 새로 알게 된 것 
**1. `require` vs `check`**
* 자바에서는 `IllegalArgumentException`, `IllegalStateException`으로 나누는 것을 코틀린에서는 `require`, `check`로 구분됨
* 인자 검증은 require, 상태 검증은 check 
```
init {
    require(amount >= BigDecimal.ZERO) { "음수 불가" }   // → IllegalArgumentException
}

fun pay() {
    check(status == PaymentStatus.PENDING) { "상태 위반" } // → IllegalStateException
}
```

**2. `data class` vs `@JvmInline value class`**
| | data class | value class |
|---|---|---|
| equals/hashCode 자동 | ⭕ | (단일 필드 자동) |
| 필드 개수 | 다중 | **단일** |
| 런타임 객체 할당 | 있음 | **없음** (JVM이 원시 값처럼 다룸) |
| 적합한 경우 | Money(amount + currency) | CardNumber(String 하나) |
-> CardNumber를 `@JvmInline value class`로 선언함 
```
@JvmInline
value class CardNumber(val value: String) {
    init { require(value.matches(Regex("\\d{16}"))) { "..." } }
    fun masked() = ...
}
```

**3. `var ... private set`**

Java
```
private Long id;
public Long id() { return id; }
// setter 없음, assignId로만 변경 가능
```
Kotlin
```
var id: Long? = null
    private set
```
-> 외부에서 읽기 가능 (`payment.id`), 쓰기는 클래스 내부만 가능

**4. Null 안정성**
* `String`은 절대 null일 수 없음 -> `Objects.requireNonNull(orderId)` 불필요
* 자바 `Optional<Payment>` -> 코틀린 `Payment?` (nullable 타입)
* 엘비스 연산자 `?:` 로 null 처리
```
private fun loadPayment(paymentId: Long): Payment =
    repo.findById(paymentId)
        ?: throw IllegalArgumentException("Payment not found: $paymentId")
```
자바의 `.orElseThrow(...)`와 의미 같음

## 핵심 코드 
```
data class Money(val amount: BigDecimal, val currency: Currency) {
    init { require(amount >= BigDecimal.ZERO) { "금액은 음수일 수 없습니다." } }

    val isPositive: Boolean get() = amount > BigDecimal.ZERO

    companion object {
        fun krw(won: Long): Money =
            Money(BigDecimal.valueOf(won), Currency.getInstance("KRW"))
    }
}

@JvmInline
value class CardNumber(val value: String) {
    init { require(value.matches(Regex("\\d{16}"))) { "카드 형식이 맞지 않습니다." } }

    fun masked(): String =
        "${value.substring(0, 4)}-****-****-${value.substring(value.length - 4)}"
}

class Payment(
    val orderId: String,
    val amount: Money,
    val cardNumber: CardNumber,
) {
    var id: Long? = null
        private set
    var status: PaymentStatus = PaymentStatus.PENDING
        private set
    var paidAt: LocalDateTime? = null
        private set

    init { require(amount.isPositive) { "결제 금액은 양수여야 합니다." } }

    fun pay() {
        check(status == PaymentStatus.PENDING) { "PENDING 상태에서만 결제 가능" }
        status = PaymentStatus.PAID
        paidAt = LocalDateTime.now()
    }

    fun refund() {
        check(status == PaymentStatus.PAID) { "PAID 상태에서만 환불 가능" }
        status = PaymentStatus.REFUNDED
    }

    fun assignId(newId: Long) {
        check(id == null) { "id는 한 번만 할당할 수 있습니다" }
        id = newId
    }
}
```
